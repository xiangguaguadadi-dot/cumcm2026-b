# 统一独立复核计划

在六条路线均定稿之前登记。目的：核对各自报告的代码/结果关系，并检验改善能否延续到未用于本轮迭代的新随机样本。

1. 各 Agent 按三轮及条件性延长规则自行完成最终选择，报告当前最佳和取舍候选。主 Agent 记录待复核快照、完整依赖散列、提交和回归结果，再生成新案例；本次复核不再产生候选迭代。
2. 使用未修改的 v1 生成逻辑，采用系统随机产生的 100 个新种子，保留 12 组场景、两道题，总计 2400 局。案例文件及其散列一次保存。所有最终候选与原始基准使用完全相同的案例。
3. 生成函数通过读取 AST 提取，避免导入原始 generate_cases.py 时重写冻结案例。使用现有冻结 evaluator 和 LocalEnv，仅将新的案例传入公开评测函数；每次评测前后检查冻结清单。
4. 先看全清局数、源清除数、异常与终止状态；存在失败时不只取成功子集计算“平均加速”。再分别计算 Q3/Q4 的每局秒/源算术均值、最差局和每组场景均值，列出退步场景。
5. 新种子在不同场景和题目复用，样本存在相关性。附加的不确定性估计按种子簇自助抽样，计算配对节省秒/源的 95% 区间；它只是本地探索性统计，未作多方案选择校正，不将其称为因果证明或正式显著性获胜。
6. 虚拟动作耗时是主要效率指标。程序运行时间和整批现实耗时分开记录；并行研究期间的机器负载与历史基准缓存影响现实运行时间，不能把它当成严格的计算速度对比。
7. 不向 Agent 回传新样本表现进行再调参。任何之后的新算法实验属于后续实验批次。本次结论覆盖新种子、相同本地分布假设，不等于新分布鲁棒性或官方 Windows 模拟器验证。

复核程序：final_review.py。程序先以 24 局自建样本做运行链路检查，基准自身比较的配对差与区间均为 0；这批链路检查样本不计入最终新样本验证，也不作为任何改进证据。

## 生成最终样本前的补充登记

在最终新样本尚未生成时，登记 A5 的 R2 当前最佳与 R3 双题均值非支配取舍都进入复核。另加入 A1 的 R10 场景取舍：它的两题总体均值被 R8 支配，但在既有回归上消除了 R8 第四问的唯一基准退步场景，且第三问逐局相同。因此用同批新样本核对该场景差异，明确作为补充候选，不更改 A1 已完成的最佳选择，不让 Agent 根据复核结果继续训练。

交付时将候选源码逐字复制到主仓库的独立快照目录，核对原始散列、提交与部署依赖后，直接对交付快照运行共同评测。原工作树和主仓库的冻结环境一致；没有辅助部署依赖的候选可统一使用主仓库作为评测根目录。记录可选 coverage_points.json 的存在状态与散列，避免快照位置改变而静默采用不同的覆盖点。
