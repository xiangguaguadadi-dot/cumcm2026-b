# 最佳方法

这个文件夹集中保存当前 **B3 方法**的可运行代码、完整评测数据、原始结果、方法说明和复核记录。复制整个文件夹后，可以独立核对成绩、重跑本地案例；不需要寻找原仓库中的其他实验目录。Python 3.10及以上，仅使用标准库。

“最佳”指截至本次归档，在本轮已测试且满足保留条件的候选中，B3的第三、四问本地平均耗时最低。它不是连续策略空间的全局最优证明，也不是官方成绩。

## 先看这两处

1. **了解第二问究竟改进了什么：** [路线B与现有第二问的比较](文档/路线B与现有第二问的比较.md)。区分原第二问的接收保证、上一轮精度研究，以及B3面向完整任务的测点选择。
2. **查看当前结果及负例：** [本轮完整报告](实验记录/REPORT.md)。包含两条路线、5个候选、两批结果、配对区间、退步场景和实际运行次数。

## 当前结果

每个案例先计算“本局总虚拟时间 ÷ 实际清除数”，再在同一题的2400个案例上取算术平均。对照为 `fusion_r5`；候选为B3。两题各30970个源，4800个案例全部清除并正常退出。

| 题目 | fusion_r5 秒/源 | B3 秒/源 | 平均减少 | 相对改善 |
|---|---:|---:|---:|---:|
| 第三问 | 229.853134 | 229.669843 | 0.183291 秒/源 | 0.079742% |
| 第四问 | 453.656492 | 450.980422 | 2.676070 秒/源 | 0.589889% |

第三问收益很小，配对差值的95%区间跨0，不能称为稳定提升。第三、四问分别有1057、743局变慢；全部负例均保留。以上均为既有暴露本地案例的回归结果，未新增盲测或官方Windows测试。这些百分比衡量完整任务耗时，**不是第二问定位误差降低的百分比**。

## 先核对原始结果，不运行求解器

终端进入本文件夹，运行：

下列命令中的 `python3` 需要是3.10或更新版本。本次整理机器自带的 `python3` 为3.9，实际验证使用 `/opt/homebrew/bin/python3.12`；在这台机器上可用该路径替换下列 `python3`。无需安装第三方依赖。

```bash
python3 -I 复现.py audit --out 验证产物/自行审计_001
```

这会检查包内文件散列和原冻结v1清单，再从保存的4800个案例行独立核对ID、源数、全清、每局时间分母和分批/分场景指标。审计本身没有新的求解器执行，不能计成又跑了一遍4800局。

## 实际重跑

```bash
python3 -I 复现.py run --suite quick --out 验证产物/自行快测_001
python3 -I 复现.py run --suite full --out 验证产物/自行全测_001
python3 -I 复现.py run --suite exposed --out 验证产物/自行4800_001
```

- `quick`实际运行120局，且是`full`的子集。
- `full`实际运行原v1的2400局。
- `exposed`实际运行两个既有批次的全部4800局，本入口不复用候选行。
- 对照指标来自已核验的fusion_r5缓存；如需实际重跑父法，增加 `--candidate baseline`，并使用新的输出目录。
- 每次输出目录必须尚不存在。可以使用本包`验证产物/`中的新目录，也可以用包外新目录；不覆盖封存的数据和结果。
- 实际耗时取决于机器与负载。现实运行秒数会变化，应核对虚拟时间、清除数、移动距离等确定性指标。

本次整理只新增归档和运行组织入口，没有改变B3策略或v1规则。打包后的独立验证范围见 [整理与验证说明](验证产物/整理与验证说明.md)。`文件清单.json`封存输入文件；`验证产物/`在封存后产生，单独记录验证所用的输入散列。
