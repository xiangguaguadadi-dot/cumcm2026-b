# 联合测站与任务路线：实施方案 v1（待审核）

2026-09-12。状态：**仅方案；尚未启动两个执行 Agent，尚未创建本轮工作树或运行实验。** 用户审核后，按本方案启动两个子 Agent；主 Agent 负责共同接口、调度、集成、审计和交付。依据为[已完成调研](REPORT.md)、[数学证明](math_bounds/REPORT.md)和[方法研究](new_methods/REPORT.md)。

## 一、我建议先做什么

先实现一个不训练的“联合替换未来测站”求解器：**共同改变 2–4 个尚未执行的测站位置，选择各站真正要测的频道，并安排它们与已知源服务的顺序。** 原策略作为可执行起点和后备续局；新计划只有通过连续覆盖认证才可生效。

两个 Agent 按模块配合，两者都覆盖第三、四问：A 负责生成并证明更省的测站布局，B 负责把这些布局变成真实在线动作及完整任务收益。A 先在 Q3 验证连续圆覆盖，再扩到 Q4 方向覆盖；B 同期完成调度接口与不改行为的接入，随后消费 A 冻结的计划接口。这样各自都能先独立推进，并保留 A-only、B-only 和 A+B 的可运行对照。

第一阶段不训练 PPO、Q 网络或世界模型。先确认新动作空间里确有可回收的收益，再决定是否值得用学习加速搜索。完整 POMDP 和大型混合整数在线求解器也不作为第一版的前置依赖。

## 二、目标与“逼近下界”的准确含义

| 层级 | 验收对象 | 目标 |
|---|---|---|
| 正确性 | 全部已登记案例 | 正常退出、实际全清、无接口越权、连续覆盖条件成立 |
| 可用改进 | 同批完整暴露回归 | Q3/Q4 分别优于当前对应最佳；保留两题各 12 组和尾部退步 |
| 主要目标 | 完整暴露回归＋冻结后的新种子确认 | Q3 平均低于 200、Q4 平均低于 400 秒/源 |
| 持续逼近 | 固定诊断子集 | 实际合法策略费用下降，与固定松下界的差距缩小；数学界改善另列 |

主指标始终是 `J=(1/m)Σ_i(T_i/N_i)`，先要求全清，不是总 T/总 N，也不把 Q3/Q4 混成一个分数。

当前锚点完整 4800 暴露案例：Q3 **229.853134**、Q4 **453.656492**；各题 2400 局、30970 源。距目标分别 29.853134/53.656492 秒，约 12.99%/11.83%。

目前 134.739/144.478 的信息约束松下界仅来自各题 48 例诊断子集；同批锚点是 218.334/443.469，不能与完整集均值混比。它们不是已知可达最优值，160 也不是已证极限。数值 DP 尚无区间算术认证，所有“离下界多远”的数值先标为诊断，不称严格最优误差证书。

固定诊断集上记录：`ΔJ=J_anchor−J_new`、`G_new=J_new−LB_fixed`。若报告 `(J_anchor−J_new)/(J_anchor−LB_fixed)`，名称只用“相对固定松下界的缺口缩小比例”，不能称“已实现最优收益的百分比”。本轮中途收紧的新下界单独出表，不能因下界升高而宣称策略变快。若候选数值低于声称的下界，先查下界/计费/全清错误。

达到 200/400 后，仍可在本轮预算内按有益方向继续；最终确认批只在研究收束和候选冻结后运行一次。

## 五、共同实现合同

### 5.1 可见状态

`PublicSnapshot` 只含：真实当前位置/频道、公共请求响应历史、成功清除频道、真实可行几何、逐频道真实 no_signal/失败 clear 点、尚待执行的站与动作、已付费用和实际剩余期限。快照不可含案例 ID、种子、组别、真实源数/坐标/朝向/半径、评分或后续真实观测。

接口：`propose(snapshot) -> Plan[]`、`verify(snapshot, plan) -> certified | counterexample | unknown`、`choose(snapshot, certified_plans) -> next_action`。只有主执行器可以调用真实 `enter/measure/clear/exit`。

每个 Plan 绑定快照 hash、父策略 hash、历史版本、未来真实坐标及频道动作、完整剩余覆盖方案、认证证据、失效条件和后备接续标识。相同公共历史产生的计划与选择必须相同；不能按测试编号或真值选择策略。

### 5.2 不漏源的核心约束

- 已执行坐标和响应不可移动；仅改变未来计划。覆盖登记绑定真实坐标、频道和响应，不能将旧站索引的“已扫”状态迁移给新坐标。
- 只路过或只测其他频道，不能算作这个频道已观测。每个拟补测频道都计真实 measure 与换频费用。
- Q3 对剩余全域做圆覆盖认证。Q4 对每频道做近邻凸包/严格裕量叶格认证，不能把 no_signal 无条件视为排除了一个 1000 米圆。
- 可以保守忽略某些过去失败 clear 提供的排除信息，以降低实现难度；这只让认证更难。未来 clear 不能预先记成已成功或已排除，必须等真实响应。
- 第一版使用“实际历史点＋完整未来保留计划”的连续证书；认证是针对完整剩余计划，不是只检查被替换的 2–4 站。
- 未定、超时、数值裕量不足均保留原可行计划。找到覆盖反例只证伪该候选布局，不证伪所有同站数布局。
- 定位区域的认证清除点、既有完整光学覆盖序列不得被新规划器静默移动。改变它们需要单独重新认证。
- 发现 16 个不同活源频道可结束额外发现，但所有已发现源仍要实际 clear 成功才可退出。其余情况保留可靠排空义务。

### 5.3 真实执行与后备

只在父法自然外层调度边界插入新规划，第一版不切断定位/光学操作的内部调用栈。检查并准备计划后再提交；执行一个自然调度单元，再以真实观测更新状态。若该单元包含父法的 near 后附加 clear 等必要调用，完整保留并逐次计费，不能为了“单步”截断它。计划中的未执行动作不是历史事实。

若新动作已执行，失败后不能恢复到执行前的机器人位置、频道或几何。必须从当前真实状态接完整后备续局，并支付全部尾费。若接续合同无法建立，停止该候选开发，先修正确性。

必须保留已付费用、实际截止时刻、近场附加 clear、部分任务进度、待覆盖区域、route successor 等语义状态。不得重新 enter 获得新时限。真实接口异常或是否接受不确定时沿用现有通信守卫，不盲重试或虚构动作成功。

## 六、第一版怎样生成更好的计划

**A 的主问题。** 选取原计划上相邻的 2 个未来站作为起点，再扩 3/4 站。将站坐标、必须由哪些站承担的频道覆盖见证、与附近已知任务的接入关系一起更新。初始候选来自原认证站、真实服务路径的几何点、由合法定位区域计算的候选与未覆盖见证；不能使用真实源坐标。

固定站归属/次序后可优化距离与圆盘/半平面约束；整个问题仍是混合离散连续、非凸的。首版用有限候选、坐标更新和组合邻域搜索，兼容标准库单文件。外部数学求解器仅可用于本地诊断，不作为上线依赖，也不据其启发式返回值声称全局最优。

每次候选提交连续分离器：发现漏检位置/朝向就加入见证重新规划；取得完整证书才能进入选择。有限见证的最优值或经证明的优化下界才可作松弛下界，任意可行见证解成本不是下界。

**B 的选择器。** 先使用不学习的显式任务费用：所有未来移动、measure、切频、clear 分支与原可执行尾段。第一版允许任务顺序改变，但不把源中心当作确定服务出口；不可预测的部分保留为近似并记录误差。

若计划费用有利、完整闭环却变慢，先查额外补测、实际终点、剩余扫描义务与 Q4 失联分支。修复后才考虑最多两层的观测分支，不直接重复旧 E3 的“加深树”。若增加假想世界，必须条件于公开历史，同址误差固定，相同可见历史共用动作；模拟来自假设模型，不是线上读取真实隐藏环境。

每次改动登记属于“多站坐标”“付费频道分配”“混合任务顺序”“观测分支”中的哪项。多个参数试探是同一轮中的变体，所有执行都计入账本。

## 七、阶段、数据和准入

### P0：冻结、等价接入与完整记账

冻结本轮代码/输入/解释器/运行器 hash。建立逐次调用和逐局账本，跑冻结规则检查、合成边界检查，以及每题 12 场景各 2 个暴露案例的父法/关闭新模块配对，共 48 世界、96 次完整执行。

必须逐请求相同，包括坐标、频道、响应、虚拟微秒、清除、退出、后备和覆盖状态；现实机器计时另记。额外真实错误/中断夹具计入账本，不能把纯单测算成策略成功样本。P0 不通过，不能进入后续性能实验。

### P1：测量新候选空间的局部余量

使用上述 48 个世界，预先按公开进度规则选每局最多两个可重规划边界，记录原始完整轨迹。候选生成器在不知道后续真值的情况下冻结，每个边界最多 6 个新计划，A0 原继续策略保留作对照。

**首版从 enter 完整重放，不新建环境克隆系统。** 每个候选在达到同一公共历史 hash 后介入；所有前缀调用重复支付并计费。计分使用真实整局 T/N，不通过拼接历史均值构造成绩。最多 48 个父法＋576 个候选＋48 个有限最优回放，即 672 次完整执行；实际缺边界、无合法候选、失败与未定都如实报告，不为凑数换世界。

事后选出的最优计划只用于诊断，不能作为可部署策略；部署选择器必须仅看公共历史。没有覆盖证书的候选不执行。

如果存在改善但幅度小，可保留并按 2→3→4 站扩展；不强制单次两站干预就省满 13%/12%。若该语法三轮均未改进，停止它。未穷举或没有经证下界的连续求解失败，不解释成整个问题无空间。

### P2：零训练闭环迭代与消融

另建 96 个开发世界（每题每场景 4 例），从未在已知历史中使用的种子生成；一经使用即为开发数据，不称盲测。主 Agent 登记可查的旧训练/开发/确认种子范围，并同时校验 world 内容，不能只靠新案例 ID 声称新样本。无法排除的历史重叠必须标注。

先比较四组：原父法、A-only 测站替换、B-only 在父计划上的调度、A+B。所有变体使用相同世界；只看实际完整任务费用，不能把两个单独收益相加当融合成绩。

每个算法版本按本仓库规则：规则检查 → quick（120 局）→保留候选 full（2400 局）→另一历史暴露批（2400 局）。开发 96 局可先淘汰无效变体；quick 是 full 子集，不再计独立证据。原始父法记录经输入/源码 hash 核对可复用虚拟指标；比较现实速度时必须同批实际重跑。

**晋级条件：** 全部完整案例正常全清；目标题在两个历史批次均比父法更快，数值差超过累计微秒舍入误差；另一题不受改动或有独立更优组件。保留均值、12 场景、P95/最差局、更快/相同/更慢、最大退步。微小但真实的改进可晋级并继续，不强设 2% 门槛把它丢掉；同样不能把 0.1% 写成重大突破。

每个明确机制方向连续三轮不晋级即停，有晋级则重置该方向计数，并在预算内继续。bug 修复沿原机制登记，不改名清空失败历史；真实错误运行保留。预算耗尽属于预算未决，不等于三轮失败或无改进空间。

### P3：冻结后的最终确认

研究收束后冻结最终单文件、依赖、参数、运行器、配对审计器与测试生成规则并提交。之后才产生 100 个新种子，按两题×12场景生成 2400 个新世界；仅运行固定锚点与最终候选，各 2400 次，共 **4800 次完整执行**。

子 Agent 不接触这批案例内容或结果作选择；主 Agent 只为运行/核验读取。与全部已知种子及 world 内容去重，排重覆盖范围写明。所有已看过的旧确认数据均视为暴露，不能复用为本次独立确认。

按共享种子跨场景聚类 bootstrap，报告两题均值与配对差的 95% 区间、全清、分组和现实耗时。点均值低于 200/400 可称“本批平均达标”；若均值区间上端仍跨过目标，就不能称统计上稳定低于门槛。正式分布和 Windows 通信另行验证，本方案不启动官方模拟器或正式测试。

最终确认不选择版本、不调参。若不通过，交付真实结果与已保留的最佳；本批随即暴露，后续研发须另立新确认批，不能再称它未见。

建议一次批准一个完整研发批次：**累计最多 8,000,000 次本地业务接口调用、60,000 次完整/部分环境执行、首个真实调用起 6 小时研究墙钟，以先到者为准；最多两个环境 worker；零训练。** 这是本轮新增费用上限，历史执行不混入。编码与读资料不算环境调用，但计入从首个调用起的研究墙钟。

额度是保守研究安排，不是声称所有候选会花完这些调用，也不保证刚好能支持某个迭代轮数。当前锚点暴露集最大请求数为 Q3 180/Q4 418，新增规划可能改变它们；没有用旧均值冒充新候选实耗。

所有 worker 使用同一原子预算账本，先登记任务与源码，再开始；计 enter、measure、clear、exit 的尝试、接受、拒绝、未知、异常及被中断调用。每个运行立即独立落盘，批次中断仍保留已付记录。整局与后缀次数分开，初版仅 full；假想规划模型的计算次数/耗时另列，不能冒充真实环境样本。

每个研究运行设置 5000 次请求的实验保护上限，明显异常时保留为失败行而非成功终止。此上限属于运行器保护，不改冻结物理规则，也不用于让策略读取剩余研究额度。预算调度为活动运行预留额度，接近总上限不再开新任务；不得为了保留好成绩而丢弃中断/失败行。

进入最终确认前须确认剩余预算足以覆盖预计整批与安全余量；不足则暂停在已冻结候选并报告验证未完成，不能只运行有利前半批。达到 6 小时后停止新增任务，已登记运行仅在其已预留调用/单局期限内结算，随后交付。

第一版新增规划开销以每局中位数≤0.5秒、P95≤2秒作为**工程目标**，不是已测结果或官方门槛。每次规划有 anytime 截止；超时返回已认证原方案。若达不到，先减少候选、复用绑定公共几何的证书、增量校验；不要直接拿完整 4800 局做算力压力试验。官方仍保留 1200 秒及实际窗口限制。

## 九、每轮交付与总交付

每轮：候选及父法 SHA、改动说明、公式/论文启发、输入角色、真实执行账本、全部原始行、规则/连续几何证据、配对统计、决定和停止计数。主 Agent 从原始行重算，不只读子 Agent 汇总。

最终：可运行单文件；逐题最佳和融合四组结果；固定下界诊断表；已验证的连续证书与失败反例；新种子确认（若完成）；总调用/运行/墙钟；负结果与研究路径；独立分支提交/推送状态。主入口是否替换由后续交付明确处理，本方案先保留为实验候选。

“失败但学到什么”也必须具体：是无认证替代布局、计划移动省但额外扫描贵、候选有余量而公共历史选不出来、预测终点失真，还是计算预算不适用。没有消融/反例时，只报告相关诊断，不单因果归因。

## 十、审核范围

建议审核的是：**两个 Agent 按几何/执行模块协作；第一轮零训练；从 2–4 个未来站联合替换开始；8M 调用/60k 执行/6 小时首批预算；冻结后一次新样本确认；原仓库与另一个会话保持隔离。**

用户认可后，主 Agent 才创建工作树、冻结执行登记并启动两个 Agent。之后各阶段在本方案范围内自动推进，按已登记条件晋级或停止，无需每轮重复询问。扩大预算、引入训练或官方测试不包含在本次方案内。
