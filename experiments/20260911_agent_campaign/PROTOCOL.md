# 六 Agent 第三、四问研究实验约定

日期：2026-09-11。六条路线均从同一份现有求解器和 LOCAL-evaluation-v1 出发。用户已授权每个 Agent 独立开展深度文献研究、设计、代码实现、实验和最多三轮迭代；无论结果好坏，必须交付完整实验报告。第五个研究方向分配两位独立 Agent。

## 分工

| ID | 方向 | 初始侧重（软约束） |
|---|---|---|
| A1_space | 全局空间搜索与移动成本 | 覆盖搜索、路径代价、整体空间决策 |
| A2_information | 信息获取效率与定位不确定性 | 主动观测、定位几何、信息与动作成本 |
| A3_coordination | 多干扰源、多频道协同决策 | 跨目标任务安排、共享观测和移动机会 |
| A4_directional | 定向发射特性与信号可见性 | 定向覆盖、信号缺失的解释、第四问特殊结构 |
| A5_learning | 数据驱动的策略学习与自动发现 | 使用共同提示词，自主探索学习方案 |
| A6_learning | 数据驱动的策略学习与自动发现 | 与 A5 使用相同研究提示词，独立探索学习方案 |

第五个方向的两位 Agent 不预先规定不同算法路线，研究提示词保持一致，仅目录与分支等运行元数据不同。

方向并不限制创造性，选择更有依据的方案时说明理由。允许使用网络、开源代码、模型、权重和数据；记录来源、版本和依赖。避免把文献调研机械地等同于照搬论文，也不以下载大模型替代可验证的设计。

## 调研与报告

先理解题目、现有代码与实际时间开销，再广泛检索相关方法。建议发现约 8–12 个相关一手来源、深读 3–5 个关键来源；这是覆盖参考，不是数量考核。至少覆盖不同竞争方法族，阅读正文或作者正式说明，不能仅凭搜索摘要声称深读。保存查询词、检索日期、URL、版本、实际读取范围及访问失败；区分深读核心与扩展发现。为每个核心来源说明问题、机制、相关证据、边界以及迁移到本题的理由。

用户补充：报告须逐篇说明实际调研了什么文献、读到什么程度、有什么启发、是否进入代码及对应轮次/函数、实验是否支持、未采用理由，形成“文献 → 启发 → 实现 → 实验”的可复查关系。下载全文不等于已完整阅读；不得把只看摘要的论文标为深读。

最终每条路线保存 experiments/<ID>/report.md、literature.json、plan.md、iteration_log.md、best.json，以及可复现的代码和结果。报告必须自包含，清楚区分原论文结论、自己的设计推断和本题实测。

## 隔离与冻结规则

每条路线在专属 Git worktree 和分支中修改，禁止修改其他路线或主分支的 solver.py。遵守项目 AGENTS.md、README.md、docs/评测标准_v1.md。冻结清单及其覆盖的环境、案例、基准和测试不可改动；原有 results/v1_full、results/v1_quick 不得覆盖。第一、二问保持固定。

求解器只能通过 enter、measure、clear、exit 及其观测决策，不能读取案例编号、真实源数据、缓存成绩、测试进度或测试场景标签。训练可以使用另行生成的模拟数据，训练种子与 v1 的 5000–5099 分离；训练期使用真值或特权教师时必须明确标注，推理期不允许使用。必须留出训练之外的开发验证数据。固定 v1 是已知回归集，不是新留出集，不按案例编号或评测场景专门优化。

保留正常终止和完整清除的可靠性；修改覆盖/停止逻辑时提供对应几何论证和实际验证。成功数无法观察到的剩余未知源不能凭经验提前判定不存在。每局 20 分钟现实限制和 100 小时虚拟限制仍适用。

## 三轮实验与最佳版本

每位 Agent 最多三轮候选迭代，每轮对应一个冻结的候选代码快照。每轮先规则检查与 quick（120 次候选），再对保留候选执行 full（2400 次候选），保留失败及回退记录。quick 与 full 是同一轮的分级检验。禁止将大量回归集参数尝试隐藏成一轮；训练/自动搜索允许内层多次评估，但必须仅用自己的训练/开发数据并完整记录预算、尝试数及选择依据。三轮预算耗尽后不得另加候选。

每次实验结束都更新 iteration_log.md，记录候选 SHA256、规则检查、结果路径、Q3/Q4 指标、错误、耗时、当前最佳 SHA256 及判断。没有提升也必须明确当前最佳仍为原版，不能只保留成功实验。

比较先检查 full 的 2400 局全部清除、正常退出和无异常，再比较第三、四问每局秒/源的平均值。若两题均不差且至少一题改善，可记为同时优于当前最佳；若一题改善另一题变差，标记取舍，保留非支配候选，不虚构加权综合分数。每个场景的退步必须单列；总体均值仅作研发摘要，不能掩盖场景缺陷或称为官方总分。基线参考：Q3 306.3004342181635 秒/源；Q4 570.8833714439976 秒/源；每题 1200/1200 局全清。

每轮通过完整评测并优于自己的当前最佳时，立即提交代码、说明和完整结果；其他轮也保存快照与结果供最终报告复查。以各路线独立最佳为准，执行中不互相传递策略，避免污染独立性；六路完成后由主 Agent 统一比较全局最佳和不同取舍。每个 Agent 只向自己的专属远端分支推送，不能合并到 main。大权重和原始下载缓存不入 Git，保留可复现下载说明与散列。

全部候选完成后，由主 Agent 核验最佳快照与运行结果、冻结文件未被更改和策略接口边界，并对各路线最佳做一次共同的新样本验证。新样本只用于最终检验，不返给 Agent 再调参。它仍是本地分布上的泛化检查，不是官方模拟器验证。

## 可用运行方式

推荐 Python：/Users/t/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3

在各自 worktree 中执行：

```sh
python -m unittest discover -s tests -v
python evaluate.py --verify-only
python evaluate.py --suite quick --candidate solver.py --out results/<ID>_r1_quick
python evaluate.py --suite full --candidate solver.py --out results/<ID>_r1_full
```

每轮使用不同目录，额外依赖尽量放在独立环境中。先阅读 tests/check_nominal.py 的参数说明，按需执行独立正常规则核验。官方 Windows 测试不在本实验内启动；本地 HTTP 行为若被更改，另做通信验证。
